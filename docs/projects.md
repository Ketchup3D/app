# Projects, import, export, and recovery

[Documentation](README.md) · [Developer README](../README.md)

File → **New project** starts a fresh project. **Open** reads `.k3d` and legacy `.ketchup` files; **Save As** defaults to `.k3d` and writes a separate project file, including the model name, geometry, camera, and snapping settings. The app bar shows the filename without its extension as a read-only model name. Opening a project or saving it under a different filename updates the name automatically. New projects show **Untitled model** until saved. On desktop, **Save** updates the opened or last saved file, preserving its extension; a project without a file opens Save As. Saves replace the destination only after writing a complete temporary file. In browsers with file-system picker support, Save and Save As prompt for a filename and location, remembering the last save directory, and update the model name after the file is written. Other browsers download a `.k3d` file by default using the current name; their download settings control the location and whether to prompt. New and Open offer Save, Discard changes, and Cancel when the current project has changes that have not been saved to a project file. Invalid files and cancelled operations leave the current project intact. Opening a project restores its saved geometry history; creating a project starts an empty history.

Both project extensions use the same document format. You can explicitly choose either extension when saving; `.k3d` is used when no supported extension is supplied. Existing `.ketchup` projects remain compatible.

File → **Import/Export → Import SketchUp (.skp)** adds geometry to the current editing level at its original location, selects it, and fits the view. Import is one undo step and keeps the current project name and save destination. Nested group/component placements become independent editable groups; face holes, solid material colors, explicit hiding, and inch-to-metre conversion are retained. Textures, transparency, scenes, annotations, and linked component definitions are omitted. The embedded reader handles legacy MFC and modern ZIP/VFF containers, but some SketchUp versions or model features may be unsupported. Files larger than 64 MiB, malformed geometry, and recursive definitions are rejected before changing the document. Cancelled or failed imports leave the project intact. Both desktop and browser imports run locally; no SketchUp installation or upload is needed. Desktop parsing uses a compiled C++ reader on the file-operation thread; browser parsing runs in a dedicated Web Worker so the workspace stays responsive. Face picking reuses cached planes and a spatial index, and the inspector reuses cached surface areas for large imported models.

**Export Wavefront OBJ (.obj)** writes visible edges and triangulated faces, including face holes, using metre coordinates with Z up. OBJ export does not include materials, dimensions, or group/component links. Desktop export uses a save dialog; browser export downloads the file. Export leaves the project destination and unsaved state unchanged.

Local autosave continues independently of project files: editing never automatically overwrites an opened `.k3d` or `.ketchup` file. The last model name, geometry (including faces, holes, face colors, and dimensions), camera, and both snapping settings are saved locally after activity settles. Geometry edits are also saved immediately in the browser. History holds the last 100 geometry operations as reversible differences for changed entities, including fill creation/deletion. Undo and redo stacks are saved with the project and local autosave, and restored when reopening. Older files without history still open normally. Invalid or incompatible optional history is discarded without discarding the model. Filename and camera changes are outside geometry history. Version 1 edge-only documents migrate automatically to version 2, filling their existing closed planar outlines; subsequent reloads preserve intentionally deleted faces. The browser storage key is unchanged for compatibility. A restored autosave with model content is treated as unsaved to a project file; use Save As to choose its destination again.

- Desktop: the platform's local application-data directory, resolved by `directories::ProjectDirs`, in `model.json`.
- Browser: `localStorage["ketchup.document.v1"]`, scoped to the current origin.
- For isolated desktop sessions/tests, set `KETCHUP_DATA_DIR` to a directory of your choice.

Local autosave failures show an Unsaved indicator with the error in its tooltip. The live model remains editable; further edits trigger another autosave attempt. Project file errors appear in a dialog and preserve the current project and its destination. An unreadable or unsupported autosave starts a clean workspace with a recovery notice. The existing saved data is not overwritten until you edit or load another project.
